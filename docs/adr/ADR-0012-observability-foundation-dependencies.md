# ADR-0012: أساس الرصد والمراقبة — التبعيات المعتمدة (structlog ومنظومة OpenTelemetry)

## الحالة
`Accepted` — 2026-07-26

## السياق
يتطلّب خادم «المستشار القانوني الذكي» (backend) أساساً رصدياً (observability) بمستوى مؤسسي يشمل:
- تسجيلاً بنيوياً بصيغة JSON (structured JSON logging)،
- تتبّعاً موزّعاً عبر OpenTelemetry (OTel)،
- وربطاً (correlation) عبر طلبات HTTP، واستعلامات قاعدة البيانات (Asyncpg)، والنداءات الخارجية الصادرة.

ويجب أن يفرض النظام خصوصية البيانات بصرامة (امتثالاً لـ ISO/IEC 27001 — الضابطان A.8.15 وA.8.16) عبر إخفاء (redaction) بيانات الاعتماد وأرقام الهواتف اليمنية، دون الإخلال بسياسات عزل الصفوف (Row-Level Security) القائمة على مبدأ الثقة الصفرية (Zero-Trust)، ولا بأهداف مستوى الخدمة (NFR ≤ ٢ ثانية للطلبات غير النموذجية).

يعمل المستودع تحت **سياسة تبعيات مقفلة (locked dependencies)** تستوجب اعتماد قرار معماري صريح قبل إضافة أي حزمة تشغيل (runtime) جديدة.

## القرار
نعتمد إضافة `structlog` وسبع (٧) حزم محدّدة من OpenTelemetry إلى `pyproject.toml` كاستثناء صريح لقائمة الحزم المقفلة:

1. `structlog` (v24.1.0+) — محرّك التسجيل البنيوي مع دعم `contextvars` وخطوط معالجة (processor pipelines).
2. `opentelemetry-api` (v1.24.0+) — واجهة التتبّع الأساسية.
3. `opentelemetry-sdk` (v1.24.0+) — تطبيق OTel SDK و`TracerProvider`.
4. `opentelemetry-instrumentation-fastapi` (v0.45b0+) — أَتْمَتة تتبّع FastAPI (ASGI).
5. `opentelemetry-instrumentation-sqlalchemy` (v0.45b0+) — تتبّع محرّك SQLAlchemy.
6. `opentelemetry-instrumentation-httpx` (v0.45b0+) — تتبّع عميل HTTP الصادر.
7. `opentelemetry-exporter-otlp-proto-http` (v1.24.0+) — مُصدِّر مقاطع OTLP عبر HTTP لمجمِّع التتبّع الإنتاجي.

## الخيارات المدروسة
- **الخيار ١: مكتبة `logging` القياسية + مُنسِّق JSON مخصّص**
  - *مرفوض*: يفتقر إلى الربط الأصيل بـ `contextvars`، وإلى خطوط المعالجة النظيفة، وإلى الدمج الكفء لمستويات السجل الذي يوفّره structlog.
- **الخيار ٢: تتبّع يدوي دون أَتْمَتة (auto-instrumentation)**
  - *مرفوض*: يفرض قدراً كبيراً من الشيفرة التكرارية (boilerplate) عبر المُوجِّهات (routers) وعملاء HTTP وجلسات قاعدة البيانات، مع خطر عالٍ لضياع حدود المقاطع (span boundaries).

## النتائج
### إيجابية
- ربطٌ موحّد عبر `X-Request-ID` / `trace_id` / `span_id` بين سجلّات التسجيل والتتبّع الموزّع.
- سياق تسجيل مربوط بـ `contextvars` عبر المهامّ غير المتزامنة (async).
- إرسال سجلّات/مقاطع عالي الإنتاجية وغير حاجب (non-blocking) عبر `BatchSpanProcessor` في بيئات الإنتاج.
- إخفاء صارم قائم على المفاتيح والتعابير النمطية (regex) دون إفساد مقاييس التطبيق أو رموز حالة HTTP.

### سلبية
- إدخال تبعيات عبورية (transitive): `protobuf`، `opentelemetry-semantic-conventions`، `wrapt`، `asgiref`.
- زيادة طفيفة في البصمة الذاكرية (memory footprint) أثناء إقلاع العملية.

### متابعات
- الإبقاء على تثبيت الحزم الصريح (pinning) في `pyproject.toml`.
- مزامنة الضوابط ذات الصلة إلى «سجل الضوابط» في Notion (المرحلة ٤).
