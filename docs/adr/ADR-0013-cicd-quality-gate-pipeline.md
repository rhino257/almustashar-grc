# ADR-0013: خط تحقّق الجودة في CI/CD وضوابط الأمن

## الحالة
`Accepted` — 2026-07-26

## السياق
يتطلّب خادم «المستشار القانوني الذكي» (backend) خط CI/CD حتميّاً ومُؤتمتاً يفرض جودة الشيفرة، وأمان الأنواع (type safety)، وتجميد عقد الـ API، وأمن التبعيات، ومنع تسرّب الأسرار، وسياسات عزل الصفوف (RLS) «فاشلة بالإغلاق» (fail-closed) قبل دمج أي شيفرة في الفرع `main`.

تُنفَّذ جميع فحوص الخط في بيئة Python 3.12 نظيفة ومعزولة، باستخدام خدمة قاعدة بيانات مخصّصة `pgvector/pgvector:pg16`.

## القرار
نُنشئ سير عمل صريحاً لبوّابة جودة CI (`.github/workflows/ci.yml` في مستودع الكود) يفرض ضوابط جودة غير قابلة للتجاوز، وترتيب تنفيذ دقيقاً للخطوات، وفصلاً لأدوار قاعدة البيانات، وفحص أسرار، وتدقيق ثغرات التبعيات، ومنع انحراف العقد (contract drift).

### ترتيب تنفيذ الخطوات والمسوّغ المعماري
1. **سحب الشيفرة (`actions/checkout@v4` مع `fetch-depth: 0`)**: يلزم كامل تاريخ Git لفحص الأسرار عبر `gitleaks` على الالتزامات (commits) السابقة.
2. **تهيئة Python 3.12 وتثبيت التبعيات (`.[dev]`)**: تُثبَّت أدوات التحليل الأمني (مثل `pip-audit`) في بيئة `[dev]` المعزولة دون المساس بتبعيات التشغيل المقفلة.
3. **`SEC-CI-003`: فحص الأسرار (`gitleaks/gitleaks-action@v2`)**: يفحص كامل المستودع وتاريخه قبل تنفيذ أي سكربتات. قائمة سماح مُحدَّدة في `.gitleaks.toml` تسمح بأسرار اختبار وهمية خاصة بالـ CI عبر تعابير نمطية ومسارات دقيقة.
4. **`SEC-CI-001`: فحص ثغرات التبعيات (`pip-audit`)**: يدقّق التبعيات المثبّتة مقابل قواعد الثغرات، ويُفشِل البناء عند وجود ثغرات (CVE) قابلة للإصلاح.
5. **التحليل الساكن للشيفرة (`ruff check`، `ruff format --check`، `mypy --strict src`)**: حلقة تغذية راجعة سريعة لالتقاط أخطاء الصياغة والتنسيق وأمان الأنواع قبل تهيئة قاعدة البيانات.
6. **إنشاء دور تطبيق مقيّد (`CREATE ROLE almustashar_app ... NOSUPERUSER NOBYPASSRLS`)**: يجب أن يسبق الهجرات كي تستطيع سكربتات Alembic إصدار عبارات `GRANT` تستهدف الدور `almustashar_app`.
7. **تشغيل هجرات Alembic (`alembic upgrade head` عبر `MIGRATION_DATABASE_URL`)**: تُنفَّذ باتصال المستخدم الأعلى (`almustashar`) للسماح بإنشاء الجداول وتعديل المخطّط وإعداد سياسات RLS (`ENABLE ROW LEVEL SECURITY`، `FORCE ROW LEVEL SECURITY`).
8. **منح صلاحيات DML على المخطّط**: يمنح صراحةً `SELECT, INSERT, UPDATE, DELETE, TRUNCATE` على كل جداول `public` للدور `almustashar_app`.
9. **`SEC-CI-002`: حارس انحراف عقد OpenAPI (`scripts/export_openapi.py` + `git diff --exit-code`)**: يُعيد توليد `contracts/openapi.json` من مسارات FastAPI ويؤكّد انعدام الفروق مقابل العقد المُلتزَم.
10. **حزمة الاختبارات (`python -m pytest -v`)**: تُنفَّذ كامل الاختبارات تحت `DATABASE_URL` (الدور المقيّد `almustashar_app`)، بما يضمن أن `test_rls.py` يتحقّق من آليّات RLS «الفاشلة بالإغلاق» والعزل بين المستأجرين وفرض `FORCE RLS` تحت قيود عدم امتياز المستخدم الأعلى.

### استراتيجية متغيّرات البيئة وعزل الأدوار
- **`DATABASE_URL`**: يتّصل كـ `almustashar_app:app_password` (`NOSUPERUSER NOBYPASSRLS`). يستخدمه تشغيل التطبيق و`pytest`.
- **`MIGRATION_DATABASE_URL`**: يتّصل كـ `almustashar:almustashar` (المستخدم الأعلى/المالك). يستخدمه Alembic ومهيّئات `test_rls.py` حصراً.
- **`OTEL_ENABLED="false"`**: يُعطّل تتبّع OpenTelemetry في الـ CI لتفادي ضجيج `ConsoleSpanExporter` على stdout ومنع مشكلات حجب `engine.sync_engine` أثناء تنفيذ سكربت تصدير OpenAPI.

### سياسة إدارة الأسرار
جميع قيم الأسرار المذكورة في `.github/workflows/ci.yml` (مثل `JWT_SECRET`، `HMAC_KEY`، `AES_KEY`، `POSTGRES_PASSWORD`) هي بيانات اعتماد **وهمية غير إنتاجية** تُستخدم حصراً للاختبار المُؤتمت داخل حاويات CI معزولة. **يُمنع منعاً باتّاً تضمين بيانات اعتماد في الشيفرة في بيئات الإنتاج**، ويجب حقن الأسرار الحقيقية حصراً عبر GitHub Environment Secrets أو إعدادات بيئة الاستضافة.

### ميزات الخط المؤجَّلة صراحةً
الميزات الآتية خارج نطاق المرحلة الحالية ومؤجَّلة صراحةً:
1. **محرّك SAST كامل**: تحليل أمني ساكن عميق (Semgrep / Bandit) — مؤجَّل لتصليب SSDLC مستقبلاً.
2. **بناء صور الحاويات وفحص ثغراتها**: تغليف صور Docker وفحص Trivy — مؤجَّل حتى تحديد طوبولوجيا النشر.
3. **النشر لبيئة التجهيز واختبارات الدخان**: نشر CD مؤتمت لعنقود التجهيز (staging) — مؤجَّل.
4. **بوّابات الاعتماد اليدوي والتراجع المؤتمت**: ضوابط إصدار CD ومشغّلات التراجع (canary/blue-green) — مؤجَّلة.

## النتائج
### إيجابية
- ضوابط أمن بثقة صفرية مضمونة على كل طلب دمج (pull request).
- التحقّق من RLS «الفاشلة بالإغلاق» تحت دور PostgreSQL مقيّد فعلي في بيئة CI.
- منع انحراف عقد الـ API وتسرّب الأسرار قبل الدمج.

### سلبية
- زيادة طفيفة في مدّة تشغيل CI بسبب إقلاع خدمة PostgreSQL الكاملة وتنفيذ `pip-audit` / `gitleaks` (~15–30 ثانية إضافية).
